프로젝트 이름은 빨간 우체통 단편영화 촬영.

프로젝트 목적은 단편영화를 만들어 영춘제라는 학교 영화 상영회에 제출 최종적으로는 영화 상영을 하기 위해서 프로젝트를 진행했어.

프로젝트 진행 기간은 3월 중순부터 11원 초.

팀 구성은 감독, 조감독, 메인 카메라 감독, 부 카메라 감독, 음향 감독, 스크립터으로 구성되어 있었는데 나는 메인 카메라 감독을 맡아 맡은 바를 착실히 수행했어. 프로젝트가 끝나고 내가 맡은 부분에 대한 호평이 많았어.

사용 기술로는 촬영,색감 보정,카메라 움직임 조절(카메라 기능 조절) 등등이 있어.

주요 기능으로는 역시 촬영 중 카메라 기능을 조정하는 것을 뽑을 수 있을 것 같아.

촬영 과정에서 어려웠던 것은 아무래도 날씨 영향이 가장 많았어. 우리가 원하는 날씨를 정할 수 있는게 아니다 보니까 힘들었지. 그리고 초반에 카메라를 처음 만져보다 보니까 카메라의 주용 기능을 능숙하게 사용하지 못해 어려움을 격었어.

카메라를 능숙하게 사용하기 위해서 남는 시간에 한번 더 보고. 다른 사람들이 쉴 떄 또 한번 가서 많이 만져보며 기능을 익혔지.

프로젝트를 하며 내가 뛰어나다고 팀이 잘되는 것도 아니고 반대로 나 하나 이상해도 팀이 잘되지 않는게 아니란 걸 알았어. 팀이 함께 노력해야 좋은 결과가 나온다는 것에서 역시 다른 사람을 배려하고 소통하며 협력하는 것이 가장 중요하다는 것을 알게 되었지.

프로젝트명: 모션 그래픽을 활용한 듀오링고 광고 제작
프로젝트 목적은 모션 그래픽을 활용하여 듀오링고의 대표 캐릭터인 듀오의 움직임을 표현하고, 이를 통해 듀오링고의 특징과 장점을 효과적으로 전달하는 광고 영상을 제작하는 것이었어. 프로젝트는 8월 후반기부터 11월 초까지 진행되었어.

팀 구성 및 역할은 팀원들과 함께 광고 제작을 진행했으며, 나는 듀오링고의 대표 캐릭터인 듀오의 움직임을 담당했어. 캐릭터의 동작과 움직임을 자연스럽게 표현하여 광고 영상의 완성도를 높이는 역할을 맡았어.

사용 기술로는 모션 그래픽 제작, 캐릭터 애니메이션, 움직임 및 타이밍 조절, 영상 편집 등이 있어. 특히 듀오 캐릭터의 움직임을 구현하고 상황에 맞게 자연스러운 동작을 표현하는 데 집중했어.

주요 기능 및 작업으로는 듀오 캐릭터의 움직임을 제작하는 것을 꼽을 수 있어. 단순히 캐릭터를 움직이는 것에서 그치지 않고 광고의 분위기와 장면의 흐름에 맞춰 움직임을 조절하여 시청자에게 더욱 생동감 있게 전달될 수 있도록 노력했어.

프로젝트 진행 과정에서 어려웠던 점은 모션 그래픽을 처음 다루면서 캐릭터의 움직임을 자연스럽게 구현하는 것이 쉽지 않았다는 점이야. 생각했던 움직임을 실제 영상으로 표현하는 과정에서 여러 어려움을 겪었고, 원하는 결과물을 만들어 내는 데에도 어려움이 있었어.

이를 해결하기 위해 팀원들과 서로 의견을 나누고 부족한 부분을 보완하며 작업을 진행했어. 혼자 해결하기 어려운 부분은 팀원들의 도움을 받고, 서로의 작업을 확인하며 수정해 나간 덕분에 큰 문제나 트러블 없이 프로젝트를 마무리할 수 있었어.

프로젝트를 통해 배운 점은 팀 프로젝트에서 개인의 능력만큼이나 팀원 간의 협력과 소통이 중요하다는 것이야. 각자 맡은 역할이 다르더라도 서로의 작업을 이해하고 부족한 부분을 도와야 좋은 결과물이 완성될 수 있다는 것을 깨달았어. 또한 처음 접하는 기술이라고 하더라도 팀원들과 함께 고민하고 노력한다면 충분히 어려움을 극복할 수 있다는 자신감을 얻었어.

나는 이 것들과는 별게로 중 고등학교를 다니는 도중에 일본어의 기초, 일본어 회화 기초, 일본어 회화 중급, 일본 문화 알아보기, 스페인어의 기초 수업을 들으며 다른 나라의 언어와 문화를 이해할 수 있게 되었어. 그리고 또 드론 동아리와 배구 동아리를 2년간 꾸준히 활동했어. 드론 동아리는 처음 입학한 1학년부터 시작해 동아리 장을 맡은 적도 있었고 선생님께 드론 조종을 잘한다는 칭찬을 받은 적도 있었어. 배구 동아리는 원래 여자 한정 동아리였어. 그런데 내가 자발적으로 남자 부원을 모으고 남자부를 창설했지. 선생님께서는 내게 배구 교본을 떄서 붙힌 것처럼 아주 자세와 실력이 좋다고 배구를 어디서 배웠느냐고 놀라시기도 했지. 앞으로는 대학 전공을 전자공학과로 복수 전공을 소프트웨어과로 정해 전기 기술자가 되고 싶어.

# PART 2. 웹사이트 제작 요구사항

위에서 입력한 정보를 활용하여 다음 조건에 맞는 포트폴리오 웹사이트를 제작해 줘.

## 1. 역할 및 목적 (Who & Why)

웹사이트의 주요 방문자는 기업 채용 담당자와 전기전자 기술팀 리더야.

내가 전기 전자에 대해 배운건 없지만 그동안 한 프로젝트나 동아리 다른 수업들에서 얻은 것이 무었인지 그것을 어떻게 전기 전자를 배우는데 사용할것인지 잘 알 수 있게 적어줘

단순히 기술 목록만 나열하지 말고, 실제 프로젝트에서 어떤 역할을 수행했고 어떤 문제를 해결했는지 보여주는 데 집중해 줘.

## 2. 디자인 방향 (How)

- 열정적이고 쉽게 포기하지 않는 다는것을 나타내는 디자인.
- - 메인 컬러: 네이비 블루(#172B4D)
- 포인트 컬러: 전기를 연상 시키는 옐로우
-전기 전자 기술자면 바로 알아볼 수 있는 숙련자 디자인을 많이 활용
- 가독성이 높은 타이포그래피 사용
- 데스크톱과 모바일에 대응하는 반응형 디자인 적용

## 3. 페이지 구성

### ① Hero Section
- 이름과 희망 직무 표시
- 나를 소개하는 한 문장
- 핵심 기술 또는 강점 표시
- 프로젝트 및 Contact 섹션으로 이동하는 버튼

### ② About Me
- 전기 기술자에 관심을 갖게 된 계기
- 나의 강점과 개발 철학
- 학습 및 협업 경험

### ③ Tech Stack
- 입력한 기술을 섹션에 맞게 알아서 분류 
- 각 기술을 어떤 프로젝트나 활동에서 활용했는지 표현
- 사용하지 않은 기술이나 경험을 임의로 추가하지 않기

### ④ Projects
- 입력한 프로젝트를 카드 형태로 배치
- 프로젝트 카드를 클릭하면 상세 내용이 모달 또는 상세 영역에 표시되도록 구현
- 프로젝트 목적, 나의 역할, 사용 기술, 주요 기능, 문제 해결 과정, 결과 및 배운 점을 포함
- 프로젝트에 이미지나 결과물이 있다면 시각적으로 표현할 수 있도록 구성

### ⑤ Activities & Experiences
- 교육, 동아리, 교내 활동, 수상, 자격증 등 입력한 경험을 표현
- 시간순 타임라인 또는 카드 형태로 구성

### ⑥ Contact
- 이메일, GitHub, 기술 블로그 등 입력한 링크 표시
- 입력하지 않은 항목은 표시하지 않기

## 4. 콘텐츠 작성 원칙

- 학생이 입력한 실제 경험을 중심으로 작성해 줘.
- 문장이 어색하다면 자연스럽고 전문적인 표현으로 다듬어 줘.
- 프로젝트의 기술적 의미와 문제 해결 과정을 강조해 줘.
- 입력하지 않은 경험, 기술, 수상, 성과를 임의로 만들어 내지 마.
- 수치로 표현된 성과가 없다면 임의의 수치를 만들지 마.
- 정보가 부족한 부분은 수정 가능한 placeholder로 표시해 줘.
- 프로젝트가 1개뿐이라면 없는 프로젝트를 추가하지 말고 입력된 프로젝트만 활용해 줘.

## 5. 개발 조건 (Technical Requirements)

반드시 다음 조건을 지켜 줘.

1. HTML5, CSS3, Vanilla JavaScript만 사용해 줘.
2. React, Next.js, Vue 등 프레임워크를 사용하지 마.
3. Node.js, Python 등의 백엔드 서버를 구축하지 마.
4. 데이터베이스나 외부 API 연결 없이 동작하는 정적 웹사이트로 제작해 줘.
5. GitHub Pages에 바로 배포할 수 있도록 프로젝트 최상위 경로에 index.html을 생성해 줘.
6. CSS, JavaScript, 이미지 파일은 별도 폴더로 분리해 줘.
7. 이미지 및 리소스 경로는 GitHub 저장소 하위 경로에서도 정상적으로 동작하도록 상대 경로를 사용해 줘.
8. 버튼, 메뉴, 프로젝트 상세 보기 등 모든 인터랙션이 정상적으로 작동하도록 구현해 줘.
9. 모바일, 태블릿, 데스크톱에서 레이아웃이 깨지지 않도록 해 줘.
10. 입력한 정보가 없는 부분은 임의로 작성하지 마.

## 6. 최종 검증

웹사이트 제작이 완료되면 다음 사항을 확인해 줘.

- 최상위 경로에 index.html이 존재하는가?
- CSS, JavaScript, 이미지 경로가 올바른가?
- GitHub Pages의 저장소 하위 경로에서도 정상적으로 작동하는가?
- 모든 버튼과 메뉴가 정상적으로 작동하는가?
- 모바일 화면에서 레이아웃이 정상적으로 표시되는가?
- 백엔드 서버 없이 정적 웹사이트로 실행 가능한가?
- 학생이 입력한 실제 경험과 임의로 생성된 정보가 혼합되지 않았는가?

마지막으로 전체 파일 구조와 각 파일의 역할, 수정해야 할 정보, GitHub Pages 배포 방법을 정리해 줘.
